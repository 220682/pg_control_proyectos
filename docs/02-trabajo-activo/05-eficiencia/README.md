# Eficiencia del flujo

## Qué vive acá

Un informe por plan analizado, con el mismo nombre base que el plan (`YYYY-MM-DD-<tema>.md`), escrito por el Analista del flujo con la plantilla `../../00-estandar-agentes/06-plantillas/10-medicion-y-eficiencia.md`: indicadores de costo, calidad, previsión y fluidez, y las mejoras propuestas a la política.

## Quién trabaja acá y cuándo

El Analista del flujo **no participa en el flujo de un plan** y el Orquestador no lo lanza. Solo trabaja cuando el Responsable humano lo invoca directamente en una sesión. Para invocarlo se le escribe, por ejemplo:

> Tú eres el analista del flujo. Trabajemos en `<tema>`. Lee el README de `docs/02-trabajo-activo/05-eficiencia/` y solo lo que necesites.

## Qué lee el Analista (y solo eso)

1. Este README y la lista de informes previos de abajo (no los abre completos: lee el que se relacione con el tema).
2. El estándar: `../../00-estandar-agentes/08-medicion-y-relevo.md` y `../../00-estandar-agentes/02-roles-y-delegacion.md` § Analista del flujo.
3. Del plan que analiza: la tabla de medición de su progreso (`../02-progreso/`), el informe del Auditor (`../04-auditoria/`), el libro de hallazgos de su plan (`../01-planes/`) y los resúmenes de cierre de sus tandas.
4. La salida del script de medición: `python scripts/medir.py --resumen --desde <fecha>`.

## Qué hace y qué no

Entrega su informe en esta carpeta, con la plantilla, y una lista de mejoras propuestas a la política, cada una con el documento que afecta. **No edita** el estándar, `AGENTS.md`, los Skills ni ninguna fuente de verdad: propone, y el Responsable humano decide. Las mejoras aprobadas se aplican en un cambio aparte.
